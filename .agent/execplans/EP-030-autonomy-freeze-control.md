# EP-030 Durable Autonomy Freeze Control

Plan status: COMPLETE

## 1. Purpose / Big Picture

Hydra's documented D5 autonomy-freeze procedure currently names a `hydra`
CLI or Auditor command that does not exist. Replacing autonomy cells manually
does not preserve the pre-freeze policy, does not expose a durable freeze
state, and can leave the persisted Governor cache serving the old matrix.

This plan adds a narrow, local owner-control seam. A tenant freeze is stored
as an additive overlay, invalidates the tenant Governor revision, and causes
new proposals to evaluate at canonical L1 while already-dispatched approved
work is not revoked. Thaw restores the previously stored autonomy matrix.

## 2. Scope

- Add a durable tenant-scoped autonomy freeze status table.
- Add Store methods for idempotent freeze, thaw, status, and audit event write.
- Make the persisted Governor provider observe freeze through its existing
  tenant revision cache.
- Add confirmation-gated `hydra-admin autonomy freeze|thaw|status` commands.
- Add integration and provider-cache tests for freeze, thaw, tenant isolation,
  idempotence, and event emission.
- Replace the placeholder D5 command wording with the real owner command and
  document the local-only evidence boundary.

## 3. Non-goals

- No direct HTTP freeze endpoint or caller-supplied tenant authority.
- No automatic cancellation, rollback, or revocation of already-dispatched
  approved envelopes.
- No changes to the deterministic Governor's L0-L5 semantics.
- No LLM, agent, Nexus, bridge, or adapter authority in the freeze path.
- No hard delete, purge, retention policy, or production database operation.
- No new dependency, Node/npm toolchain, or layer-law exception.
- No claim that staging D5 evidence or EP-010 production readiness is complete.

## 4. Context and Orientation

`crates/store/src/autonomy.rs` persists the tenant matrix and policy revision,
while `crates/kernel/src/policy_provider.rs` rebuilds a cached Governor when
that revision changes. `crates/fabric/src/rest/autonomy.rs` exposes only the
existing admin matrix replacement path. `crates/admin-cli/src/main.rs` is the
existing confirmation-gated owner tool. `OPERATIONS.md` D5 currently describes
an absent `hydra cell freeze` command. The overlay must preserve stored cells
so thaw is reversible and must emit the same durable event/outbox authority
used by other autonomy mutations.

## 7. Interfaces and Contracts

- `autonomy_freeze` is keyed by Hydra `tenant_id`; absent rows mean active.
- Status is additive and soft-state only: `active` or `frozen`.
- A frozen tenant's stored matrix is read unchanged but every resolved cell
  is presented to the Governor as L1. L1 therefore remains the sole source of
  the `SuggestOnly` behavior.
- `autonomy freeze TENANT_ID REASON` requires
  `HYDRA_ADMIN_CONFIRM=I_UNDERSTAND` and a non-empty bounded reason.
- `autonomy thaw TENANT_ID` requires the same confirmation and restores the
  stored matrix without deleting the freeze row.
- `autonomy status TENANT_ID` is read-only and prints no secrets or records.
- Repeating an equivalent freeze/thaw is idempotent: it returns current state
  without creating a duplicate event or revision bump.
- Every state change appends the typed
  `hydra.crm.autonomy.freeze_changed.v1` event through Store's canonical event
  and outbox path with tenant, actor, status, and bounded reason only.
- A freeze increments the existing tenant policy revision, so all Kernel
  instances reconstruct their cached Governor before later decisions.
- An already-dispatched `ExecuteToken` remains attributable and is not
  canceled; new proposals and post-freeze approvals observe L1.

## 11. Idempotence and Recovery

Freeze/thaw writes are upserts and preserve the row in both states. Repeating
the same requested state is a read-equivalent operation with no duplicate
event. If a transaction fails, neither the freeze row, revision bump, nor
event is published. If a process stops after commit, the next Governor lookup
reads the durable revision and reconstructs the overlay. Operators must inspect
already-dispatched work separately; this plan never auto-cancels or replays it.
