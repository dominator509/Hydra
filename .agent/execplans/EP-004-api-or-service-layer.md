# EP-004 Service Layer: fabric REST+MCP, LLM Router, TOKENKILLER, Bridge Host + Conformance

## 1. Purpose / Big Picture
The system grows its nervous system: HTTP/MCP surface (SPEC-003), multi-provider LLM router with structural PII gate, the full TOKENKILLER pipeline (SPEC-009), the Wasmtime bridge host with capability grants, and the conformance harness — plus the first hand-written fixture adapter proving the WIT contract before any agent ever generates one.

## 13. Surprises & Discoveries
- 2026-07-07 - The normative bridge WIT needed one syntax escape to be consumable by the current toolchain: the adapter function named `list` must be spelled `%list` in source because `list` is a reserved WIT keyword. `wasm-tools component wit` parsed the file cleanly after that change, which preserves the intended ABI name without inventing a different operation.
- 2026-07-07 - On this Windows machine, `wit-bindgen` guest exports for the `wasm32-wasip2` target already produce a component binary. Re-running `wasm-tools component new` on that output fails with `decoding a component is not supported`, so the truthful M1 build path is to stage the built artifact directly into `adapters/memcrm.wasm`.
- 2026-07-07 - `wasm-tools` 1.240.0 here still needs `validate --features component-model` for component binaries. Plain `wasm-tools validate adapters/memcrm.wasm` rejected the finished artifact even though the same file validated cleanly once the component-model feature was enabled.
- 2026-07-07 - `wasmtime 38.0.4` no longer accepts the older `bindgen!({ async: true })` option from the reference sketch. The working bridge-host binding path uses `imports: { default: async | trappable }`, `exports: { default: async }`, a `HasSelf<HostState>` linker projection, and a no-op `types::Host` marker impl so the generated world glue matches the current macro surface.
- 2026-07-07 - The Rust-built `wasm32-wasip2` fixture component still imports preview2 resources such as `wasi:io/poll@0.2.6`. `cargo test -p bridge-host host_` now gets as far as component instantiation and then fails until bridge-host links the matching WASI preview2/resource implementations.
- 2026-07-07 - The fixture adapter's preview2 imports are satisfied by the full `wasi:cli/imports` world rather than a one-off `poll` shim. Adding `wasmtime_wasi::p2::add_to_linker_async` plus a `WasiCtx`/`ResourceTable`-backed `WasiView` on `HostState` resolved the missing `wasi:io/poll@0.2.6` resource wiring and let the bridge-host tests reach real adapter execution.
## 14. Decision Log
- 2026-07-07 - Added `Cargo.toml`, `COMMANDS.md`, `ENVIRONMENT.md`, and `DECISIONS.md` even though they were outside the original M1 file list. Reason: adding the fixture adapter as a workspace member and introducing a new adapter-build command/target requirement would otherwise leave the repo's command surface and dependency record false.
- 2026-07-07 - Escaped the WIT function name as `%list` in `wit/hydra-bridge.wit` instead of renaming the operation. Smallest reversible fix because the current WIT parser treats `list` as a reserved keyword, and the escape preserves the intended ABI spelling from SPEC-003/reference without inventing a semantically different method name.
- 2026-07-07 - Kept `scripts/build-adapters.sh` to a direct copy of the built `wasm32-wasip2` artifact into `adapters/memcrm.wasm` rather than wrapping it with `wasm-tools component new`. Smallest truthful path because the `wit-bindgen` output is already a component on this target, and double-componentizing it fails immediately.
- 2026-07-07 - Installed the Rust `wasm32-wasip2` target locally once the new M1 build script proved it was the only missing prerequisite. Smallest recovery move because EP-004 M1 validation is defined around a real component build, not a placeholder artifact or a native-only cargo check.
- 2026-07-07 - Kept the bridge-host Wasmtime binding layer on `imports: async | trappable` plus `exports: async` instead of forcing non-trappable host calls. Smallest reversible match to the current `wasmtime 38.0.4` macro API because it preserves the reference design's outer trap channel while still generating async `call_*` bindings for the guest adapter surface.
- 2026-07-07 - Allowed `unsafe_code` only in `crates/bridge-host` and nowhere else. Smallest workable exception because `wasmtime`'s generated component bindings emit internal `unsafe` blocks, while `ARCHITECTURE.md` already constrains Wasmtime to bridge-host as the sole adapter boundary.
- 2026-07-07 - Added `wasmtime-wasi` 38.0.4 and stored a `WasiCtx` plus `ResourceTable` directly inside `HostState` instead of inventing custom preview2 resource shims. Smallest truthful fix because the Rust-built fixture component imports the standard WASI preview2 world, and `wasmtime_wasi::p2::add_to_linker_async` satisfies that contract without broadening Hydra's trust boundary beyond bridge-host.
- 2026-07-07 - Updated the fuel exhaustion test to inspect the full `anyhow` error chain instead of only `to_string()`. Smallest reversible fix because Wasmtime still raises the expected out-of-fuel trap, but the outer `call describe` context string alone hid the inner fuel/trap wording after the new WASI layer started wrapping the guest call path.
