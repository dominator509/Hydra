# EP-004 Service Layer: fabric REST+MCP, LLM Router, TOKENKILLER, Bridge Host + Conformance

## 1. Purpose / Big Picture
The system grows its nervous system: HTTP/MCP surface (SPEC-003), multi-provider LLM router with structural PII gate, the full TOKENKILLER pipeline (SPEC-009), the Wasmtime bridge host with capability grants, and the conformance harness — plus the first hand-written fixture adapter proving the WIT contract before any agent ever generates one.

## 2. Scope
crates/{fabric,llm-router,tokenkiller,bridge-host,bridge-wit}, wit/hydra-bridge.wit, one fixture adapter (Rust→wasm, in-memory CRM), tests/fixtures/tk-corpus, scripts/cache-hit-audit.sh, kernel executor path (Decision::Execute → apply+events).

## 3. Non-goals
No shell views (EP-005); no OAuth provider (EP-006 — Bearer stub validates a static dev token behind HYDRA_ENV=dev); no agent behaviors beyond a smoke `concierge.ping` route proving the TK call path; no GraphQL; no real SuiteCRM adapter (EP-007 canary uses it, synthesis is agent-runtime feature not build-time).

## 7. Interfaces and Contracts
Exact WIT world `hydra:bridge@1.0.0` as reference file (adapter exports describe/probe/introspect-schema/list/get/upsert/delete/changes-since; host exports http/secret/kv/sql/log/now-ms). TK: `Session::complete(route:&str, s: Segments, tail: Tail) -> Result<Contracted, TkError>` — the ONLY function agents may call for LLM work (TK-1). REST routes exactly SPEC-003 list.

## 13. Surprises & Discoveries
- 2026-07-07 - The normative bridge WIT needed one syntax escape to be consumable by the current toolchain: the adapter function named `list` must be spelled `%list` in source because `list` is a reserved WIT keyword. `wasm-tools component wit` parsed the file cleanly after that change, which preserves the intended ABI name without inventing a different operation.
- 2026-07-07 - On this Windows machine, `wit-bindgen` guest exports for the `wasm32-wasip2` target already produce a component binary. Re-running `wasm-tools component new` on that output fails with `decoding a component is not supported`, so the truthful M1 build path is to stage the built artifact directly into `adapters/memcrm.wasm`.
- 2026-07-07 - `wasm-tools` 1.240.0 here still needs `validate --features component-model` for component binaries. Plain `wasm-tools validate adapters/memcrm.wasm` rejected the finished artifact even though the same file validated cleanly once the component-model feature was enabled.
- 2026-07-07 - `wasmtime 38.0.4` no longer accepts the older `bindgen!({ async: true })` option from the reference sketch. The working bridge-host binding path uses `imports: { default: async | trappable }`, `exports: { default: async }`, a `HasSelf<HostState>` linker projection, and a no-op `types::Host` marker impl so the generated world glue matches the current macro surface.
- 2026-07-07 - The Rust-built `wasm32-wasip2` fixture component still imports preview2 resources such as `wasi:io/poll@0.2.6`. `cargo test -p bridge-host host_` now gets as far as component instantiation and then fails until bridge-host links the matching WASI preview2/resource implementations.
- 2026-07-07 - The fixture adapter's preview2 imports are satisfied by the full `wasi:cli/imports` world rather than a one-off `poll` shim. Adding `wasmtime_wasi::p2::add_to_linker_async` plus a `WasiCtx`/`ResourceTable`-backed `WasiView` on `HostState` resolved the missing `wasi:io/poll@0.2.6` resource wiring and let the bridge-host tests reach real adapter execution.
- 2026-07-07 - The M3 conformance harness executes the staged `adapters/memcrm.wasm` artifact, not the fixture crate source directly. After fixing `fixtures/adapter-memcrm/src/lib.rs`, the conformance suite kept reporting the old non-idempotent behavior until `bash scripts/build-adapters.sh` rebuilt the component.
- 2026-07-07 - Seeding hundreds of records through `probe` consumes real adapter fuel because the fixture builds the in-memory dataset inside the component. The conformance harness needed a much larger fuel grant than the lightweight M2 smoke tests once pagination/property coverage started resetting the adapter with 250-record seeds.
- 2026-07-07 - `crates/tokenkiller` and `crates/llm-router` were still placeholders when M4 started. The smallest truthful seam was to land TOKENKILLER behind local `Router` and `LedgerSink` traits plus a `StoreLedgerSink` adapter, so `Session::complete` is real now without inventing provider wiring before M5.
- 2026-07-07 - `cargo deny check` is currently red on `Apache-2.0 WITH LLVM-exception` from the existing Wasmtime/Cranelift stack. That is a repo license-policy gap rather than a TOKENKILLER implementation bug, and changing the allow-list is a legal-policy decision instead of a code-only fix.
- 2026-07-07 - The cleanest M5 integration point was to keep `llm-router` implementing the existing `tokenkiller::Router` trait instead of backtracking through another shared crate extraction. That let the real router land now and keeps M6 free to drive cache-hit replay through `Session::complete` without rewriting the TOKENKILLER seam again.
- 2026-07-07 - Accurate fallback accounting needed one extra field in `tokenkiller::CompletionResponse`: the route config’s preferred provider is not sufficient once M5 can walk a chain. Recording the actual responding provider avoids false ledger rows when the first provider fails or when later degradation prefers a private provider.
- 2026-07-07 - The `>=0.97` replay target is not reachable if every route’s first cold call counts against the audited ratio: three 14-call sequences cap out below that even with perfect later hits. The workable M6 shape is one warm-up call per route followed by fourteen measured calls, with the audit logging every measured `prefix_sha` so unstable S0-S2 bytes still surface immediately when the ratio slips.
- 2026-07-07 - `scripts/cache-hit-audit.sh` needed to inject the repo’s documented local `DATABASE_URL` default when the environment variable is absent. Without that, the replay gate failed in `store`’s SQLx macros before any TOKENKILLER cache math ran, and `verify.sh` would have inherited the same false-negative path.
- 2026-07-07 - `ExecuteToken` only carries the envelope id, not tenant or the serialized action body. The truthful executor seam therefore needs a store-side `get_by_id` lookup before it can apply `Decision::Execute`, and the narrowest evidence for that path is a real kernel integration test that seeds an approved envelope plus entity row.
- 2026-07-07 - `store::EnvelopesRepo::transition` takes `&dyn Clock` through an async boundary, which makes the future non-`Send` when called from `async_trait` service methods. For the first fabric approval/rejection slice, the narrow reversible workaround is to transition the envelope in memory and persist it with `save`, leaving the repo-level transition helper available for non-`async_trait` callers such as the integration tests.
- 2026-07-07 - The first full `bash scripts/test-integration.sh` rerun after the entity slice did not fail on code correctness; it failed earlier with `rustc-LLVM ERROR: IO failure on output stream: no space on device` while linking `wasmtime-wasi` and `bridge-host`. Removing rebuildable `target\debug\incremental` artifacts was enough to recover the local validator without touching source.
- 2026-07-07 - `bridge-host`'s `conformance` test `c1_crud_roundtrip` can run long enough that Cargo prints `has been running for over 60 seconds` on this machine even when the suite is healthy. The truthful recovery move was to keep polling rather than aborting a test that ultimately finished green in about 99 seconds.
- 2026-07-07 - `GET /v1/autonomy/cells` currently returns the store's canonical ordering rather than the caller's request order. The first `PUT /v1/autonomy/cells` implementation echoed the input vector, which made the contract round-trip disagree with the immediate follow-up `GET`; the stable fix is for the mutating route to return the persisted listing instead of weakening parity expectations.
